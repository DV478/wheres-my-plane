# User feedback — 2026-11-07

Live site: https://wheres-my-plane.pages.dev (prod, running commit `69ff38d`).
User tested after Phase 0–3 ship + on-demand cron switchover. This is their raw
feedback after seeing the actual product for the first time end-to-end.

## User's direct observations (verbatim summary)

1. **Scheduler panel is cryptic to a new user.** The Start/Stop panel just sits there
   with no instructions, no explanation of what "Start" does or what the user is
   supposed to do. "As a new user what am I supposed to do here?" Should have a
   tooltip or inline hint explaining purpose + expected behaviour.

2. **Map click popup is thin and worthless.** On `/app/map`, clicking a traffic dot
   shows: tail reg (`G-WOFM`), ICAO hex (`GWOFM`), ICAO type code (`A109`), altitude,
   speed, heading, and a "Look up in my flights →" link. **No airline. No origin /
   destination. No status. No photo.** Compare to Flightradar24's popup, which the
   user screenshotted: large hero photo, scheduled dep/arr times, actual status,
   equipment with full type + reg, callsign, flight number, airline — a rich,
   genuinely useful card. Ours looks half-built.

3. **Backgrounds are plain and unexciting.** Flat dark-navy background across every
   app page. No texture, no imagery, no atmosphere. Does not feel like a product
   someone would keep using.

4. **Confidently wrong information on the flight detail page.** Added `QR4` (LHR →
   DOH, Sat 7 Nov, 14:15 dep). The flight detail page shows:
   - Status: **Boarding** ✓
   - Punctuality: **"pending — Punctuality feeds arrive in Phase 3."** ❌
     Phase 3 is shipped. This string should not exist anymore. Confidently wrong.
   - Aircraft: **"Aircraft not yet assigned — Airlines often publish the tail
     number only on the day of travel."** ❌ The FR24 screenshot shows the actual
     tail is `A7-API`, equipment `A388`, callsign `QTR4E`. So the tail *is*
     assigned, we just failed to fetch it. The user asked why the app says it
     isn't — and they're right to ask.

5. **Missing: disruption monitor by airport.** User says they explicitly asked for
   this earlier and it's not in `IMPLEMENTATION_PLAN.md`. Needs investigation —
   either we scoped it out without flagging, or lost the ask.

6. **Priorities for the roadmap:** Voice Q&A (Phase 4), Photo spotter (Phase 5),
   Price monitoring (Phase 6) are **deferred.** The basic product is crap and must
   be fixed before building new surfaces. Quote: "the basic product itself is crap
   right now."

## What the user wants next

The user explicitly asked for three things, in this order:

1. **Opus "reflection" agent** → `REFLECTION_2026_11_07.md`. Not a fix list. A
   reflection on *why* everything shipped substandard. What patterns led here.
   What we should have done differently at each phase. Honest.
2. **UI/UX inspection agent** → `UX_INSPECTION_2026_11_07.md`. Inspect the live
   product and the code; produce concrete UX feedback with severity ratings.
3. **Opus planning agent** (after 1 and 2 land) → a plan to lift the baseline
   product quality. Deferred features (Voice, Photo, Price) stay deferred.
